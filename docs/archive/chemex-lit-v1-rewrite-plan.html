核心原则：新核心重写，旧代码只作行为参考。生产核心压缩到约 20–30 个模块、一条管线、一个数据模型体系、一个 LLM 客户端、一个审阅入口。

核心设计目标

v1 核心只解决一件事

PDF → 文档证据 → 反应候选 → 结构候选 → 验证 → 反应记录 → 人工审阅

明确删除的核心复杂度

  • 不在核心中做自动进化。
  • 不维护多套自动/半自动 orchestrator。
  • 不做通用 Agent 平台。
  • 不做通用 DAG/插件框架。
  • 不维护多个 Reviewer。
  • 不允许运行时从仓库根目录读取 prompt/config。
  • 不让 Oracle 从头生成最终记录。
  • 不允许实验模块反向依赖生产核心。

核心约束

  • 一条 Pipeline
  • 一套 Pydantic Schema
  • 一个 ArtifactStore
  • 一个 OpenAI-compatible LLM Client
  • 一套 Prompt Registry
  • 一个 Review 页面
  • 一个确定性 Assembler
  • 所有不确定项进入 ReviewQueue，不做静默修复

最终架构

PDF → MinerUAdapter → DocumentBundle
DocumentBundle → TextExtractor → TableExtractor → StructureExtractor
TextExtractor ↓ TableExtractor ↓ StructureExtractor
CandidateSet → Validator → DeterministicAssembler
DeterministicAssembler → 存在歧义？
否 → ReactionRecord → records.jsonl + review.jsonl + review.html
是 → Optional Adjudicator → ReactionRecord

唯一核心数据模型（9 个）

不要继续扩展几十个相似 Schema。核心控制在以下 9 个模型。

模型用途
RunRequest运行输入：pdf_path、output_dir、config_path、external_structures、resume
EvidenceRef所有结论必须能回到证据：evidence_id、kind、page、source_path、text、bbox
DocumentBundleMinerU 输出的唯一内部表示：document_id、markdown、images、evidence
CompoundRef化合物引用：label、name、smiles、role
ReactionCandidate正文和表格提取统一输出：reactants、products、reagents、solvents、conditions、yield、evidence_ids、confidence
StructureCandidate结构提取输出：compound_label、smiles、evidence_ids、confidence
ValidationIssueG1–G4 统一表示：code、severity、target_id、message、suggested_value
ReactionRecordv1 正式公共 Schema：schema_version、reaction_id、compounds、conditions、evidence、confidence、review_status、issues
RunSummary运行结果：run_id、status、records_count、review_count、output_dir、stages
关键简化：不再保留 TextCandidate、TableCandidate 等多套近似模型；ReactionCandidate 同时服务于 text 和 table 提取。DocumentBundle 吸收 layout_indexer.py 的能力，不再保留独立 Evidence Bundle 体系。

Pipeline 设计

pipeline.py 只负责顺序和状态，不实现具体化学逻辑。
class Pipeline: def __init__(self, mineru, text_extractor, table_extractor, structure_extractor, validator, assembler, store, adjudicator=None) -> None: ... def run(self, request: RunRequest) -> RunSummary: document = self.mineru.convert(request.pdf_path) reaction_candidates = self._extract_reactions(document) structure_candidates = self._extract_structures(document, request.external_structures) issues = self.validator.validate(reaction_candidates, structure_candidates) records = self.assembler.assemble(reaction_candidates, structure_candidates, issues) records = self._adjudicate_ambiguous(records, document) self.store.write_records(records) return self._build_summary(records)

并行度约束

  • 只允许三个并行任务：TextExtractor、TableExtractor、StructureExtractor
  • 不再使用 parallel_workers: 30
  • 默认最多 3 个 stage worker
  • 视觉请求单独限制并发为 1–2

提取器设计

不引入通用插件系统，只定义小型 Protocol：

class ReactionExtractor(Protocol): def extract(self, document: DocumentBundle) -> List[ReactionCandidate]: ...

三个实现

  • TextExtractor
  • TableExtractor
  • StructureExtractor

每个 Extractor 只做三件事

  1. 选择证据。
  2. 调用 LLM。
  3. 将响应解析为正式 Candidate Schema。
Extractor 不允许：写最终记录；自行执行审阅；自行调用 RDKit 修复；读取其他 Extractor 的 JSONL；决定 Pipeline 状态。

LLM 层精简

当前多 backend/resolver/hybrid/agent bridge 体系全部退出核心。

只保留一个接口

class LLMClient: def complete( self, model: ModelSpec, prompt: str, images: Sequence[Path] = (), ) -> dict: ...

llm/client.py 职责

  • payload 构建
  • httpx 请求
  • 重试
  • 错误分类
  • JSON 解析
  • 请求日志

删除

  • AgentBridgeBackend
  • AgentCliBackend
  • HybridBackend
  • ConfigResolver
  • 多层 TaskConfig/ModelConfig/ProviderConfig
  • 自动 fallback
重要：正式版不应静默切换模型。失败就明确失败；需要 fallback 时由配置显式指定第二模型。

统一 Issue 编码

编码含义
V001SMILES_PARSE_FAILED
V002VALENCE_INVALID
V003STEREO_UNSPECIFIED
V004DUPLICATE_STRUCTURE
V005LABEL_STRUCTURE_CONFLICT
V006ROLE_INCONSISTENT
V007STRUCTURE_COLLAPSE
验证原则：
  1. 验证器只报告问题。
  2. 允许确定性 canonicalization。
  3. 不允许自动 LLM 修改原始 SMILES。
  4. 修复建议进入 suggested_value。
  5. 所有实际修正必须经过 Assembler 明确采用或人工审阅。

这样可以删除当前复杂且难以验证的自动 repair loop。

Assembler 与 Oracle

DeterministicAssembler

Assembler 按固定规则执行：

  1. 标准化 compound label。
  2. 合并重复 ReactionCandidate。
  3. 按标签关联 StructureCandidate。
  4. 标签缺失时才使用页码和证据邻近度。
  5. 计算置信度。
  6. 附加 ValidationIssue。
  7. 生成 ReactionRecord。
置信度 = 0.35 × reaction evidence + 0.25 × structure match + 0.20 × source agreement + 0.20 × validation quality

Adjudicator（原 Oracle）

只处理：

  • 多个候选结构冲突。
  • 产品/底物角色冲突。
  • 多个表格行对应同一 reaction。
  • 证据相互矛盾。
Adjudicator 不得：创建原始候选；修改无歧义记录；覆盖 RDKit 硬错误；无证据生成 SMILES。

默认关闭，只有 needs_review 记录才可能调用。

自动与半自动统一

彻底删除 SemiManualOrchestrator。

人工 SMILES 作为外部 StructureCandidate 输入：

chemex-lit run paper.pdf --structures manual_structures.jsonl # 或者： chemex-lit resume outputs/run-id --structures manual_structures.jsonl

自动模式和人工模式只在 StructureCandidate 来源上不同：

  • 自动：StructureExtractor → StructureCandidate
  • 人工：manual.jsonl → StructureCandidate
统一后处理链：后续验证、组装、审阅完全相同。这可以消除大量自动/半自动重复逻辑。

恢复规则

  • Stage 完成且输入哈希不变：跳过。
  • 输入或配置变化：从该 Stage 开始重新执行。
  • 文件写入采用临时文件加原子替换。
  • 不再维护多套 checkpoint 格式。

重构实施方式

不要在原包上边移动边修复。建议建立新包并行实现。

阶段 A：冻结旧行为

  • 保存脱敏后的 archive/pre-v1 tag
  • 选择 3–5 个代表性运行结果
  • 建立 characterization tests
  • 冻结正式 ReactionRecord 1.0 Schema

阶段 B：建立新核心

按以下顺序实现：

  1. models.py
  2. store.py
  3. config.py
  4. llm/client.py
  5. mineru.py
  6. 三个 Extractor
  7. Validator
  8. Assembler
  9. Pipeline
  10. Review
  11. CLI

阶段 C：能力迁移

每项能力都必须满足：

旧 fixture 输入 ↓ 新模块输出 ↓ Schema 合法 ↓ 关键字段不低于旧基线

不迁移旧类名和私有方法，只迁移业务行为。

阶段 D：删除旧包

  • 当新核心完成完整回归后，删除原 chemex/
  • src/chemex_lit/ 成为唯一实现
  • 删除兼容层
  • 发布 1.0.0rc1

最终判定标准

重构完成后应达到：

  • 只有一条生产 Pipeline。
  • 自动和人工输入共用同一条后处理链。
  • 不超过 30 个生产模块。
  • 不存在超过约 500 行的核心业务模块。
  • 所有运行资源包含在 wheel 中。
  • 默认测试命令覆盖全部测试。
  • 没有运行时根目录依赖。
  • 没有重复 Schema、Prompt、Reviewer、Checkpoint。
  • 没有自动静默 fallback。
  • 没有“0 记录但 success”。
  • 实验代码不随正式 wheel 安装。
  • 删除旧代码不会影响正式 v1 功能。
总结：这次重构最重要的原则是——以新的数据契约和单一 Pipeline 为中心重新实现，不以保留旧类和旧目录为目标。

发布阻断项

本地审计发现的结构性、打包与合规风险，必须在首个稳定版之前解决。

风险严重度影响解决方向
当前不是 Git 仓库 阻断 无版本历史、无法 CI、无法发布 初始化私有仓库，脱敏后提交历史快照
main.py ~1188 行、orchestrator.py ~965 行、semi_manual.py ~2860 行 阻断 职责过载，难以维护与测试 按功能拆分为 CLI / pipeline / extraction 模块
main.py 后半部分重新定义 run/resume/status 阻断 模块级符号被覆盖，结构性隐患 删除重复定义，统一命令注册
测试：424 项中 14 失败、12 错误 阻断 SMILES 契约漂移、集成失败、Windows 路径问题 修复真实失败，统一测试目录
toolkit/tests/ 不在默认 pytest 范围且独立运行 9 个导入错误 高 测试覆盖割裂，归档代码破坏独立测试 合并到 tests/，修复或移除归档 import
ruff / build 不可用且未列入 dev 依赖 高 无法保证代码质量与可发布包 加入 pyproject.toml dev 依赖与 CI
wheel 安装后 prompts / 配置不可访问 阻断 源码目录可运行，wheel 不可运行 采用 src layout，将 prompts 和默认配置打包为包内资源
credentials.yaml 含 5 个非占位敏感配置 阻断 首次推送即有泄露风险 轮换密钥，历史扫描，提交前 secret scan
PyPI 上的 chemex 已被占用 阻断 无法以 pip install chemex 发布 统一更名为 chemex-lit
声明 Python ≥3.9，但 3.9 已 EOL 高 正式版不应以 EOL 版本为最低 最低版本提升至 3.11

迁移映射

当前内容建议处理
main.py拆分为 cli/ 下独立命令模块
orchestrator.py, pipeline_steps.py移入 pipeline/，编排层只组织步骤，不实现化学逻辑
提取器模块统一进入 extraction/
G1–G4、RDKit、视觉检查统一进入 validation/
Oracle、RecordAssembler进入 assembly/
eval/、chem_compare/、baseline合并为 evaluation/
agents/ 与 skills/合并为唯一 prompt 源；manifest 决定运行版本
harness / webui / mcp / evolution / molcodev1 暂放 experimental/，稳定核心不得反向依赖
toolkit/_archive删除；历史由 Git tag 保存
.sisyphus/plans有效内容转 GitHub Issues / ADR，其余归档
根目录 HTML 报告移入 outputs/ 或 docs/archive/
原始论文 PDF移至私有 benchmark 仓库；Git LFS 不能解决版权问题
.opencode/node_modules永远不提交；无关 skill 移出正式代码仓库
四条边界：
  1. 正式公开 API 只包含 CLI、配置格式和 JSONL Schema，不承诺所有 Python 内部类稳定。
  2. 输出记录增加 schema_version。
  3. 每次运行生成 run_manifest.json，记录软件版本、prompt 版本、模型、配置哈希、PDF 哈希和依赖版本。
  4. Prompt 只能有一个权威来源，不能继续同时维护 agents/*.yaml 和 skills/*/best.yaml。

仓库初始化

  • 先建为私有仓库
  • 轮换当前所有真实 API Key
  • 排除 credentials.yaml、outputs/、node_modules/、原始论文、HTML 产物
  • 对待提交内容运行 secret scan
  • 创建脱敏历史快照提交，标记 archive/pre-v1-20260717
  • 从 refactor/v1 分支开始目录重构
  • 达到 RC 标准后再决定是否公开

分支策略

采用轻量 trunk-based 模式：

  • main：始终可发布。
  • feat/*、fix/*、refactor/*：短期分支。
  • release/1.0：只在 RC 稳定期使用。
  • Squash merge，提交标题使用 Conventional Commits。
  • 不设长期 develop 分支。

main Ruleset 建议

  • 必须经 PR
  • 禁止 force push 和删除
  • 必须通过 CI、package smoke、test checks
  • 必须解决所有 review conversation
  • 多人团队要求 1 个批准；单人项目可暂设 0 个批准，但仍强制 PR + CI
  • 对 v* tag 单独设置不可修改、不可删除规则

正式发布验收条件

1.0.0 发布必须全部满足：

  • 默认 pytest 包含原 toolkit/tests，且 100% 通过。
  • Windows/Ubuntu × Python 3.11–3.13 全绿。
  • ruff format --check、ruff check、类型检查全绿。
  • wheel 和 sdist 均能构建；从 wheel 安装后 prompts、模板、默认配置仍可访问。
  • chemex-lit --version、--help、check、合成 fixture pipeline smoke 全部通过。
  • 不再出现“0 条记录但状态仍为 success”的静默成功；至少区分 success、completed_empty、partial、failed。
  • 至少建立 5 篇不同布局论文的私有回归集；正式发布以“不低于冻结基线”为 gate。
  • JSONL Schema 100% 可验证，记录 schema_version。
  • 没有真实密钥、原始输出、node_modules、受版权限制论文进入公开历史。
  • README、安装指南、配置参考、输出 Schema、迁移指南、LICENSE、CHANGELOG、SECURITY、CITATION 完整。
  • 1.0.0rc1 后不再增加功能，只修阻断问题。

# ChemEx-Lit 审核 HTML 修改方案

日期：2026-09-10。状态：设计提案，尚未实现。以当前代码为基线。

## 1. 目标与范围

将审核 HTML 改为以单个反应为中心的证据审核工作台。审核者应能在同一界面回答：

1. 这个反应是否真实存在，是否有遗漏、重复或错误归属？
2. 每项条件是否来自正确的实验、表格行和脚注？
3. 每个底物、产物和添加剂的身份、角色与结构是否正确？
4. 底物与产物的立体化学是否忠实于文献？
5. 有金标时，提取结果与金标具体差在哪里？
6. 哪些内容已经人工确认，哪些仍然待定，修订是否已正式应用？

首个可用版本必须包含条件、结构、立体化学、可选金标比对，以及确认与修订闭环。
仅有更美观的结构展示，不能视为完成。保留单一 Pipeline 和单一 review 生成/应用入口。

## 2. 当前实现的具体缺口

| 当前代码事实 | 影响 | 修改方向 |
| --- | --- | --- |
| 模板只有纵向反应卡片，无交互 | 无法记录确认、定位问题或续审 | 反应导航、分项审核、草稿与正式提交 |
| generate_review 仅渲染 reactants/products | 添加剂结构不可审核 | 增加结构化参与物侧车数据 |
| reagents/solvents 为字符串列表 | 缺少结构、用量、角色和证据关联 | 保留 v1 字段，另建有版本的审核上下文 |
| evidence.jsonl 已保存，HTML 未使用 | 无法核对原文、页码和图示 | 将证据接入字段与化合物卡片 |
| 只有反应级 evidence_ids | 不能声称精确定位每个字段来源 | 区分字段证据与反应级参考证据 |
| 立体检查只覆盖部分未指定手性中心 | 无逐中心检查、E/Z 或原文对照 | 增加确定性立体分析与人工判定 |
| evaluate 未进行化学结构等价或立体比较 | 现有匹配率不能代表结构正确率 | 新增分层结构比较及明确分母 |
| 修改后无 error 即可能 accepted | 小修订可能被误读为整条人工确认 | 分离机器状态与人工审核状态 |
| review 和 review-apply 均读取原 records.jsonl | 再次审核/修订可能忽略已有更正 | 显式记录当前修订版本和基础哈希 |
| 当前生成测试仅断言文件与 reaction_id 存在 | 无法证明可用性 | 增加真实审核流程和视觉验收 |

review-policy.md 也存在契约偏差：示例使用斜杠路径，而实现使用点路径；文档列出
corrected 状态但模型不支持；描述的重组装行为在 apply_corrections 中不存在。
实施时必须同步修正文档及契约测试。

## 3. 页面信息架构

桌面采用三栏：左侧反应队列，中间当前反应，右侧证据查看器。参考比例为 20% / 50% / 30%；
在较窄屏幕将证据移至抽屉，避免结构图与表格被挤压。

```text
文献名称 · 当前数据版本 · 人工审核进度 · 金标版本 · 导入/导出审核包
┌──────────────┬────────────────────────────┬──────────────────┐
│ 搜索/筛选     │ 反应编号、原文位置、状态      │ 原文/图示/表格     │
│ 反应缩略图    │ 底物 → 产物（添加剂在箭头旁） │ 页码、上下文、缩放  │
│ 待审/有差异   │ 条件 | 结构 | 立体 | 金标    │ 当前选中证据高亮   │
│ 完成 n/m     │ 分项值、证据入口、确认操作    │ 来源缺失说明       │
├──────────────┴────────────────────────────┴──────────────────┤
│ 上一反应 · 下一待审项 · 当前修订摘要 · 确认本反应 · 导出审核包   │
└─────────────────────────────────────────────────────────────┘
```

- 默认定位首个未审且有阻断问题的反应；可按原文顺序查看全部反应。
- 搜索 reaction_id、化合物标签、名称和原文位置；筛选未审、缺结构、立体待定、金标差异。
- 卡片同时显示“机器校验”和“人工审核”，不将 confidence 当成人工可信度。
- 结构图优先，SMILES 默认折叠但可复制；字号、缩放、键盘焦点与状态文字均可辨识。
- 状态使用文字和图标，不仅依赖红绿颜色。大图按需加载，切换反应不丢草稿。
- 无记录、证据缺失、渲染失败、未提供金标都应有明确空态，不能留白。

## 4. 条件审核：逐字段，同时检查完整性

条件表固定列为：字段、提取值、文献原值/单位、来源、差异/问题、审核结论。

首批覆盖已有温度、时间、收率、试剂、溶剂；同时扩展审核上下文以承载：
用量、当量、浓度、催化剂/配体负载、气氛/压力、加料顺序、阶段条件、光照/电化学条件。
区分反应条件和后处理/纯化，区分分离收率与 NMR/GC 收率；ee、er、dr 单独显示。

约束：

- 缺失值显示“未提取/来源待确认”，不能直接解释成“文献未报告”。
- 室温、回流、温度范围和升温程序保留原文；不得强制压成一个温度数值。
- 多步/一锅反应按步骤显示条件归属，通用步骤与表格例外/脚注共同可见。
- 若现有抽取链路未提供扩展字段，显示“当前输出未覆盖”，并允许人工补录；
  页面布局本身不能被算作这些字段的提取能力。
- 每项提供“确认正确、修订、待定、不适用”；后两项要求简短理由。
- 设置“条件完整性”检查项：即使已有字段全部正确，遗漏关键条件也不能完成条件审核。

## 5. 结构审核：逐参与物确认

按底物、产物、添加剂/催化剂/配体、溶剂分组。每张卡片展示：
稳定参与物 ID、原文标签/名称、角色、结构图、SMILES、原文结构裁图、来源与机器问题。

审核者分别确认“身份及角色”和“结构连接关系”，检查电荷、盐/对离子、同位素、
保护基、取代位置及是否漏掉参与物。支持新增、移除、调整角色，并记录原因。
同一物质在不同反应中的归属独立审核；共享结构可复用渲染，不能连带确认所有反应。

添加剂不能仅由名称在审核环节自动猜出 SMILES。无可信结构时展示名称与“结构未解析”；
人工结构输入继续使用 StructureCandidate JSONL，并由 Core 分配和关联候选。
为避免同名/同标签误归属，应通过任务、反应和参与物关联元数据定位候选。
不扩展第二条结构生成或自动修复通道。

初版支持 SMILES 文本修订和重新生成预览；分子绘图编辑器可后续增加。
若静态页面不能可靠重绘新 SMILES，必须标注“旧图，修订尚未验证”，禁止以旧图确认新值。

## 6. 立体化学审核：与连接关系独立

每个底物和产物有独立立体审核区，支持原子编号、楔线/虚线放大，显示可识别的
四面体中心及 R/S、双键 E/Z、已指定/未指定状态。编号必须绑定本次分子与渲染版本。

人工结论包括：与文献一致、立体信息遗漏、构型错误、文献未指定、不适用、证据不足。
支持记录相对构型、外消旋、混合物和工具不支持的立体类型，不强行映射为绝对 R/S。
ee/dr 数值作为相关证据显示，但不能据此凭空确定绝对构型。

- 工具未发现手性中心，不等于人工已经确认“不适用”。
- @/@@ 或 SMILES 字符串差异不能直接判断构型相反；先建立原子对应，再比较立体属性。
- 连接关系一致而立体不同，必须单独标为“立体差异”。
- 原文没有指定构型时，不要求猜出构型；忠实保留未知可以通过审核，附来源说明。
- 原文模糊、轴手性或增强立体等能力未覆盖时显示“无法自动判定”，交给人工并保留原因。

## 7. 金标准：先对齐，再比对，始终可回溯

建议增加 review 的可选 --gold 参数（拟议接口，当前尚不支持）。显式提供的文件优先；
后续重生成可使用运行元数据中已登记的路径与哈希。不递归猜测工作区内哪份文件是金标。
没有金标不阻断普通审核；指定但无效的文件必须报告校验错误。

金标通过 models.py 中有版本的模型校验；若已有外部格式，使用显式适配器并报告
不支持/丢失字段。记录金标文件名、版本、哈希、条目数和加载结果。

### 对齐规则

1. 优先使用同一文献命名空间内的稳定反应 ID 或显式映射。
2. 再以文献位置、反应编号、标签等证据生成候选；歧义交人工选择。
3. 不只依靠结构完全相同来配对，否则结构错误会被隐藏为“未匹配”。
4. 反应内按角色和参与物身份建立一对一映射，不按数组位置直接比较。
5. 单独列出仅提取存在、仅金标存在、匹配歧义、重复 ID，不让它们从页面消失。

### 展示和判定

同一参与物展示“文献裁图 | 提取结构 | 金标结构”，支持放大；提取与金标使用相同
绘图设置，在可靠原子映射下对齐共同骨架并高亮差异。映射不唯一时不绘制误导性高亮。

比较结果分为：完全一致、连接关系不同、仅立体不同、立体指定程度不同、
电荷/盐/同位素差异、单侧缺失、无法比较。比较采用分子图与立体语义，不比较 PNG 或原始字符串。
默认保留电荷、盐组分、同位素与互变异构差异；可选归一化策略必须具名、可见、可追溯。

金标缺少结构或立体信息时标为“该维度未标注”，不判提取错误。金标自身可能错误，
允许“质疑金标”并附文献证据，不能自动用金标覆盖预测或自动完成人工确认。
支持先隐藏金标做盲审，再揭示比对结果，并记录是否已查看金标。

## 8. 审核状态与修订闭环

保留 ReactionRecord v1 的 accepted / needs_review / rejected 契约。
新增独立人工状态：未审、审核中、已确认、待解决、已否决；字段/参与物决定聚合状态。
“已修订”作为事件展示，不新增到 v1 review_status 枚举。

确认整条反应需满足：反应身份和完整性已核对；所有必需条件项、参与物身份/结构、
底物产物立体项已确认或有依据的不适用；无阻断错误；金标歧义/差异已处理或有理由保留。
没有金标时金标维度不计入完成门槛。允许确认无字段修改的记录。

静态 HTML 采用离线审核包：

1. 在页面查看证据、确认或修订，显示未导出变更数量。
2. 导出版本化审核包，包含基础记录哈希、目标 ID、旧值/新值、结论、理由和证据 ID。
3. 通过 review-apply 统一校验应用；正式审核人由明确输入提供，不由模型代填。
4. Core 检查版本冲突、目标合法性和化学约束，通过 ArtifactStore 写入修订、决定与审计。
5. 重新生成 HTML，显示当前有效修订版本和正式应用结果。

浏览器下载只是待提交输入；不表示运行目录已更新。浏览器缓存仅作尽力恢复，
必须提供可导出/导入草稿，不依赖 file:// 下 localStorage 保证持久性。
浏览器不直接写生产文件，也不在静态页面中隐式调用 LLM。

修订累积应用于当前有效版本；保留原始 records.jsonl。旧审核包遇到哈希不符时拒绝盲目覆盖。
结构修改使对应结构/立体确认失效；角色或成员变化使反应完整性确认失效；
证据或金标变更使相关确认失效。重复提交用提交 ID 去重。
“拒绝”是明确人工决定，不能被随后一次无错误校验自动改成接受。

## 9. 数据与代码落点

v1 公共字段保持兼容，以可选、有版本的侧车记录补足信息；新公共记录均定义在 models.py。

| 拟新增模型/产物 | 职责 |
| --- | --- |
| ReviewContext / review_context.jsonl | 稳定参与物 ID、扩展条件、步骤、字段证据和候选关联 |
| ReviewDecision / review_decisions.jsonl | 每个审核目标的结论、理由、审核人、记录哈希 |
| ReviewSubmission / 导入审核包 | 修改操作、基础版本、唯一提交 ID；明确允许编辑的目标 |
| GoldComparison / gold_comparison.jsonl | 金标版本、对齐依据、逐维度比较结果和不可比原因 |
| review_assets/ | 本地结构图、证据裁图和必要的打包资源 |

旧运行没有字段证据时只能展示“反应级参考”，不能伪造字段映射；无法恢复的参与物身份
必须明确标记并要求映射。运行内稳定 ID 不直接依赖数组下标，修订增删不能错绑确认。

- review.py：唯一生成器/应用器，组装视图、审核状态聚合、导入校验和审计。
- resources/templates 及打包静态资源：页面布局、导航、表单与离线导出。
- chemistry.py：确定性结构渲染、立体标注、分层比较；不生成或修复化学结构。
- evaluation.py：共享比较逻辑，新增指标，保留旧指标语义并明确版本。
- pipeline.py：传递证据、候选溯源与审核上下文，不增加第二条编排流程。
- cli.py：薄入口，增加金标/数据版本选项与审核包适配；保留旧 correction 数组兼容入口。
- store.py：所有生产产物写入；审核人、提交 ID、前后值和状态均入审计。

模板开启自动转义，内嵌 JSON 安全编码；文献文本视为不可信内容。
资源路径需验证在允许的运行目录/已登记来源内，生成安全文件名；支持中文、空格和 Windows 路径。
页面离线可用，无 CDN 必需依赖；缺少 RDKit 时明确“渲染/比较不可用”，不得显示通过。

## 10. 实施顺序与交付门槛

### 第一阶段：可读、可追溯

接入证据，完成三栏布局、反应导航、条件表、结构卡片、立体信息及全部失败空态。
建立审核上下文和稳定 ID；同时以旧运行验证降级展示。交付可交互页面，但不宣称审核闭环完成。

### 第二阶段：可确认、可修订

实现分项确认、审核包导入导出、累积修订、状态聚合、失效规则、审计和重新渲染。
添加剂人工结构接入与扩展条件补录在本阶段完成。至此无金标审核可实际使用。

### 第三阶段：金标比对与发布验收

完成金标适配、人工映射、结构/立体差异展示、未匹配队列和指标。
三阶段全部通过，才满足本次四项核心需求。后续增强可包括绘图编辑器、批量操作和多审核者协调。

### 验收用例

| 场景 | 必须达到的结果 |
| --- | --- |
| 普通单步反应 | 每项条件和每个参与物均可定位证据并独立确认 |
| 添加剂只有名称 | 显示未解析；不会猜结构或被整条确认跳过 |
| 条件有多阶段、脚注例外 | 显示原值和归属，不强行合成单值 |
| 无任何字段修改 | 仍可完成人工确认并写入审计 |
| SMILES 改变但未重新生成图 | 提示旧图，不能用旧图确认修订结构 |
| 等价的不同 SMILES | 显示化学一致，不制造字符串差异 |
| 对映异构、E/Z 翻转、未指定构型 | 分别正确分类；未知不当作一致或不适用 |
| 金标条目乱序、重复标签、缺项 | 不按索引错配，歧义与遗漏单独可见 |
| 金标结构缺失或无法解析 | 标记未标注/无法比较，不算错误或通过 |
| 连续两次修改不同字段 | 第二次保留第一次结果；旧包冲突可解释 |
| 已确认结构后再次修改 | 自动撤销受影响确认，保留历史记录 |
| 已否决记录再修订条件 | 不因机器校验无错误自动接受 |
| 无 RDKit、无证据、零记录 | 有清楚降级提示，零记录保持 completed_empty 语义 |
| 离线、中文路径、长标签、窄屏 | 无必需网络请求，布局可读、操作可达 |

自动测试覆盖状态机、数据兼容、结构/立体比较、XSS 转义、路径校验和应用闭环，
所有外部服务 mock。浏览器验收至少完整执行一次“打开→核对→修订→导出→应用→重开”，
并对上述代表场景检查截图，不以 HTML 中含某个字符串代替可用性验收。

新增指标分别报告匹配覆盖率、可比较结构数及一致率、可比较立体数及一致率、
人工确认完成度；明确分母与不可比较数量。人工完成率、金标一致率、机器通过率不能混用。

发布前运行完整 pytest、Ruff、Pyright、构建与 twine 校验，并验证安装包内资源可用；
同步 README、chemex-lit-skill/SKILL.md、references 和 tests/test_skill_docs.py 对应契约。

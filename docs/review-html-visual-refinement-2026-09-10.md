# ChemEx-Lit 审核 HTML：结构图片优先的优化方案

日期：2026-09-10。状态：进一步设计方案，尚未修改生产实现。
本方案细化 review-html-redesign-2026-09-10.md 的视觉交付要求，保留其中的审核与审计契约。

## 1. 截图问题与代码根因

当前后端已经调用 RDKit：review.py 的 _render_participant_image 同时生成 PNG 和 SVG，
PNG 经 ArtifactStore 写入 review_assets。问题出在模板的显示分支：

```html
{% if p.svg %}
<div class="svg-container">{{ p.svg }}</div>
{% elif p.image %}
<img src="{{ p.image }}" ...>
{% endif %}
```

generate_review 开启了 Jinja 自动转义，因此 SVG 被显示为 XML 文本；
又因为 SVG 字符串存在，PNG 分支不会执行。截图中的长篇 path 坐标就是这一问题的表现。
所以首要修复是图片交付链路，而非继续增加审核控件。

其他视觉问题：

- 参与物纵向堆叠，没有底物到产物的空间关系，无法快速读懂反应。
- SMILES、内部 ID、状态与操作过早出现，结构图片没有获得主体位置。
- 三栏常驻导致结构区域变窄；证据栏只有短文本时仍占据大量空白。
- 当前证据显示论文标题/作者，不能据此判断它支持当前反应，必须标注关联程度。
- 条件表将同一个 c.value 同时放入“提取值”和“文献原值”，不能形成真实核对。

## 2. 第一优先级：稳定显示 RDKit 图片

### 生成端

将渲染输出统一为图片资源描述，不把 SVG 源码当作页面内容字段。
建议包含 asset_id、svg_path、png_path、结构哈希、绘图配置哈希、渲染状态及错误原因。
公开资源描述模型放入 models.py，文件统一经 ArtifactStore 写入。

- 从 SMILES 解析分子，生成二维坐标；不能改变输入化学语义来追求图面整齐。
- RDKit 输出 SVG 文件作为清晰缩放主图；同步生成高分辨率 PNG 作为后备。
- 快速修复可先直接显示当前已经生成的 PNG；最终统一使用 SVG 文件路径。
- 文件名使用结构与绘图配置的哈希，覆盖 RDKit 版本、图像尺寸、标注模式和高亮参数；
  不只依赖化合物标签，避免碰撞、缓存旧图和不同模式相互覆盖。
- 结构相同且绘图设置相同可复用资源；提取结构和金标结构均走同一渲染器。
- 每个有效 SMILES 必须得到可加载图片或明确失败状态。失败不得留下大块源码或空白。

### HTML 端

```html
<figure class="molecule-card">
  <img class="molecule-image"
       src="review_assets/STRUCTURE_HASH.svg"
       data-fallback-src="review_assets/STRUCTURE_HASH.png"
       alt="产物 20 的化学结构" width="420" height="280">
  <figcaption>产物 20</figcaption>
</figure>
```

以上路径是拟议示例。生成器填入真实资源路径，并正确处理 URL 编码。
图片错误监听器尝试 PNG 一次，仍失败则显示“结构图加载失败”与重生成指引，防止回退循环。
首屏主图优先加载，非当前反应的图延迟加载。

不通过全局关闭自动转义解决问题，也不对任意来源 SVG 使用 safe/innerHTML。
统一以 img 加载本地生成资源，文献文本和名称继续安全转义。

默认交付 review.html 与 review_assets 目录，移动时必须一起移动。
可后续提供单文件版本，将经验证的图片转为 data URI；单文件会增大体积，应明确区别。
只双击 HTML 就能浏览，不依赖网络、CDN 或前端安装 RDKit。

## 3. 首屏应是一张可读的反应图

桌面默认两栏：左侧 220–260 px 反应队列，右侧主工作区。证据默认在需要时打开为
约 360 px 的侧栏；打开后保留主图最小宽度，窄屏改为抽屉，不压缩结构到无法辨认。

```text
反应 2 / 11   ·   原文 Scheme / Entry   ·   人工未审

┌──────────────────── 反应总览 ────────────────────┐
│                                                 │
│  [底物 19 结构图]  +  [另一底物结构图]             │
│                         ─────────→ [产物 20 图] │
│                          催化剂 · 溶剂           │
│                          温度 · 时间             │
│                                      收率 82%   │
└─────────────────────────────────────────────────┘

[条件] [参与物结构] [立体化学] [金标比对]

当前选择的审核内容与操作；点击图可放大、看原文或进入该参与物审核。
```

图中数值仅为布局示意，不是当前文献提取结果。

- 反应总览用 RDKit 单分子图片配合 HTML 的加号和箭头组合，便于点击单个参与物；
  不需要先补齐原子映射或构造可能丢失角色信息的反应 SMILES。
- 首屏展示完整底物与产物关系。多组分使用可滚动反应画布和明显滚动提示，
  同时提供适应视窗与放大；不能把图缩到可读下限以下，也不能静默隐藏组分。
- 添加剂名称在箭头附近摘要显示；关键催化剂、手性配体或用户标记的参与物
  在箭头下方配独立小结构图。全部添加剂仍可在参与物页查看。
- 关键性优先来自已明确的角色，不根据名称猜结构；无结构显示小型缺失占位卡。
- 复杂多步反应按步骤切换，不能把中间体和各阶段条件混画成单步反应。
- 总览默认无原子编号、无长 SMILES、无内部 participant_id、无常驻理由输入框。

## 4. 图片尺寸与化学绘图规范

| 使用位置 | 建议显示尺寸 | 显示内容 |
| --- | --- | --- |
| 反应队列 | 120 × 72 px 缩略图 | 主要产物与简短编号；仅作定位 |
| 反应总览 | 每分子约 260–360 × 200–260 px | 完整结构、楔线/虚线与短标签 |
| 参与物审核卡 | 360–440 × 260–320 px | 结构主体，点击后显示证据与操作 |
| 结构放大/立体审核 | 约 720 × 480 px 起 | 可切换原子编号和立体标注 |
| 金标双图比对 | 每图不少于约 320 × 240 px | 同尺寸、同绘图设置、可靠映射下对齐 |

尺寸是布局起点，长链、大环和复杂多环结构需要自适应画布与放大。
PNG 按约两倍显示尺寸输出，SVG 保持向量清晰度；图片采用 object-fit: contain，
不裁剪分子边缘。白色画布、适当留白、统一键线和杂原子配色，文字不覆盖键。
不能逐图任意拉伸或为填满卡片而扭曲比例。

同一比对组优先统一键长与共同骨架方向；不要把大小不同的分子都强行填满相同矩形。
楔线、虚线和双键几何必须清晰；通过旋转或重新布局改善可读性时仍保留立体语义。

## 5. 四个审核视图的具体简化

### 条件

先显示一行摘要：温度、时间、溶剂、催化体系、收率。点击某项打开字段详情与原文证据。
详细表只有真实原文来源存在时才显示原值；缺少原值显示“未关联”，不可复制提取值冒充原文。
理由输入框在选择待定/修订时展开，避免每行挤满控件。

### 参与物结构

使用两列图片卡片，卡片首先显示图和标签，其次角色、状态及紧凑操作。
名称、SMILES、候选来源、内部 ID 放在详情中；复制 SMILES 仍应一键可达。
点击卡片进入“文献裁图 ↔ 提取结构”的并排查看模式。
原文裁图必须保留可识别标签和足够上下文，不只截出孤立的几个键。

### 立体化学

以放大的结构图为主体，提供“普通图 / 立体标注图 / 原子编号图”切换。
标注图显示工具可判定的 R/S、E/Z，并对待核对中心/键高亮；旁边短列表与图中编号对应。
编号表与图片基于同一分子对象或有明确映射，不能在 canonicalize 后直接复用旧索引。
不能只列原子索引而不在图上给出位置，也不能只用颜色表示差异。
未指定或工具不支持的构型明确显示，禁止由绘图外观自动推断“已确认”。

### 金标比对

先显示提取与金标的两张大图；原文裁图可作为第三张展开，不在窄屏硬塞三图。
同一参与物身份先完成配对，然后生成两侧图片；差异标签放在图下。
支持“原图 / 差异高亮”切换，连接关系差异与立体差异分别表达。
可靠原子映射下对齐共同骨架；映射有歧义时仅并排展示并提示，不能制造精确高亮。
没有金标不显示空的比较画布；明确提示未提供并保留其余审核功能。

## 6. 证据与状态必须让位于阅读

- 点击条件定位文本/表格，点击结构定位图示；不默认用论文标题替代当前反应证据。
- 仅有反应级证据时，在证据面板标注关联层级；顶部显示一条紧凑提醒，详细解释折叠。
- 严重阻断错误可常驻，普通技术说明不能使用大面积黄色横幅抢占结构空间。
- 对用户统一显示中文状态：未审核、已确认、待解决、已否决、机器校验通过；
  clean、resolved、unreviewed 等内部值放入详情。
- 页脚只保留上一反应、下一待审项、确认本反应、导出；参与物操作跟随选中卡片显示。
- 审核人输入安排在正式导出/提交区域，避免每张卡片重复。

## 7. 渲染与修订一致性

图片资源绑定实际渲染的结构哈希，而非文件大小。结构修订后，旧图立即标记为旧版本，
相应结构和立体确认失效。静态 HTML 中的新 SMILES 不会自行变成已验证图片：
导出、应用、重新生成后才能获得正式的新图。
如后续提供本地预览服务，也必须复用 chemistry.py 的渲染器和 review.py 的应用入口。

将图像加载失败、RDKit 缺失、SMILES 无效、SMILES 缺失分成不同状态，
方便区分“前端没有加载”与“后端不能画”。错误详情可展开，默认不输出堆栈或 SVG 源码。

## 8. 实施顺序与验收

1. 修复图片加载：先使用已有 PNG，随后将 SVG 持久化并通过 img 引用；验证回退。
2. 重排首屏：反应图置顶，主工作区增宽，证据按需展开，收起技术信息。
3. 建立普通图、立体标注图、金标比对图三套渲染模式，共享资源缓存与版本绑定。
4. 调整逐项审核操作，完成真实浏览器视觉验收，再交付用户。

必须满足的验收标准：

- 正常页面正文不出现 XML 声明、svg/path 源码或长坐标串。
- 所有当前反应有效结构图片完成加载，浏览器 naturalWidth > 0；
  仅检查 img 标签存在或 PNG 文件存在不算通过。
- 1440 × 900 视窗下，简单反应无需滚动即可看见底物、产物、方向和条件摘要。
- 复杂反应不裁剪结构；横向扩展与放大入口清晰，所有参与物可达。
- 100% 显示比例下结构标签与楔线可辨认；放大不因低分辨率而影响审核。
- 添加剂有 SMILES 时能显示结构；没有时明确占位，不猜测、不隐藏。
- 提取/金标并排可见，立体差异在图中可定位，而非只显示文字结论。
- 手动制造 SVG 加载失败可回退 PNG；两者失败时提供明确提示。
- 修改 SMILES 后不会用旧图确认新结构；再次生成得到对应新图。
- 离线、中文路径、空格路径可用；窄屏下没有相互覆盖的表格和操作按钮。

测试分两层：自动验证图片文件、哈希、模板转义、回退与版本行为；浏览器实际打开
生成的 HTML，检查加载结果并截图核对普通、立体、多组分、金标差异和缺失结构场景。
最终交付必须包含一份使用真实 ReactionRecord 生成、实际可打开的示例审核包和验收截图，
不能只交静态设计稿或生成成功的日志。
